## Архитектура и функционал сайта

### 1. 🎨 Дизайн и темы (Тёмная / Светлая тема)
- **CSS-архитектура:** CSS Custom Properties (`:root` — тёмная по умолчанию, `[data-theme="light"]`) в `styles.css?v=6`.
- **Приоритет темы:** явный выбор пользователя (`localStorage: avtotema_theme`) → системная тема устройства (`prefers-color-scheme`) → тёмная (бренд).
- **Живое следование за системой:** пока выбор не сделан, тема меняется вслед за переключением системы (`matchMedia('change')` в `theme.js`).
- **Переключатель темы (🌙 / ☀️):** кнопка в шапке всех страниц; клик фиксирует выбор навсегда.
- **Защита от мигания (Anti-FOUC):** инлайн-скрипт в `<head>` всех HTML учитывает и localStorage, и prefers-color-scheme до отрисовки DOM.

### 2. 🏎️ Слайдер «Главные премьеры и тренды» (Hero Carousel)
- **Модуль:** `hero_slider.js` — двухколоночная карусель на главной странице.
- **Данные:** собственный кураторский список `SLIDES_DATA` — автоновости из банка сюда НЕ попадают автоматически.
- **Возможности:** Автопереключение каждые 6 сек, пауза при наведении, свайпы, кнопки `‹`/`›`, индикаторы, Ken Burns zoom.

### 3. ❤️ Система лайков и аналитика реакций
- **Модуль:** `likes.js` — анонимный движок лайков с анимацией `❤️ +1`.
- **Витрина:** детерминированный стартовый посев (18–59) + реальные клики читателей.
- **Аналитика в админке:** честный учёт только реальных кликов (`bonusMap` в `localStorage`), топ-статьи, фильтры по рубрикам.

### 4. 🎬 Мгновенный локальный рендеринг видео 9:16 (Shorts / Reels)
- **Технология:** HTML5 Canvas (1080x1920) + `MediaRecorder` прямо в браузере админки, без сторонних ключей и сервера.
- **Функции:** градиенты, Ken Burns zoom фото, форматированный заголовок, бейджи, таймлайн, экспорт WebM/MP4.

### 5. 📱 Интерактивный предпросмотр постов Telegram
- В админке перед отправкой генерируется живая карточка сообщения Telegram (фото, эмодзи рубрики, время чтения, разделители, инлайн-кнопки).

### 6. 🌐 Конвейер автонаполнения (`fetch_news.js`, воркфлоу `auto_news.yml` — 07:00 и 15:00 UTC)
Полная цепочка защиты качества, каждый этап может остановить статью:

1. **Сбор:** RSS 9 источников (*Motor1 Global, CarScoops, Electrek, InsideEVs, Autocar UK, Car and Driver, Motor.ru, Quto.ru, Авто Mail.ru*). Дедупликация ссылок через `state/seen_news.json` (авто-обрезка до 2000 записей). Выбор по одной новости с запуска, ленты чередуются по кругу.
2. **Тело материала:** если лента отдаёт `content:encoded` заметно длиннее анонса — берётся он (до 1600 знаков на перевод); иначе анонс.
3. **Перевод по цепочке поставщиков:** Google gtx → зеркало `clients5.google.com` → MyMemory. После перевода проверяется доля кириллицы: сбой → статья пропускается БЕЗ пометки «виденной» и повторится в следующем запуске (на сайт непереведённый текст попасть не может).
4. **Дедупликация тем:** нормализованные заголовки сравниваются со всеми статьями банка и внутри партии (порог схожести 0.6) — одна премьера у двух СМИ не задвоится.
5. **Сборка текста:** разбивка на предложения → 3–4 абзаца; при нехватке объёма добавляется рубрикный контекстный абзац (по 3 чередующихся варианта на каждую из 5 рубрик в `RUBRIC_CONTEXT`). Материалы короче ~350 знаков НЕ публикуются вовсе.
6. **Фото:** поиск по бренду/типу кузова в Wikimedia Commons API (JPEG ≥700px, thumb 1280) → скачивание в `images/auto/art-N.jpg` с указанием автора и лицензии CC. Нет бренда или сбой → тематический fallback из фото сайта (`FALLBACK_POOLS`).
7. **Метаданные:** рубрика по ключевым словам (`detectTag`), ЧПУ-слаг транслитерацией (`slugify`, до 80 симв., уникализация), честное время чтения (знаки ÷ 1100, мин. 1).
8. **Запись в банки данных** (вставкой перед закрывающим маркером, ручные статьи не затрагиваются): `script.js → ARTICLE_BANK` (карточка+анонс), `article_content.js → BODIES + SOURCES` (абзацы+первоисточник), `article_images.js → SLUGS + IMAGES`.
9. **Автосборка и пуш:** далее воркфлоу вызывает `generate_articles.js`, коммитит от имени `github-actions[bot]` и пушит; GitHub Pages пересобирает сайт (~1 мин).

Тест без записи файлов: `NEWS_DRY_RUN=1 node .github/workflows/fetch_news.js`.

### 7. 📤 Автопостинг в Telegram (`daily_post.yml` — каждые 6 часов)
- **Выбор статьи (`publish_daily.js`):** сначала публикуются самые свежие неопубликованные (максимальный номер вне `state/posted.json`) — автоновости попадают в канал сразу после сайта. Повторы исключены; при исчерпании банка пост не отправляется.
- **Пост:** фото статьи (`sendPhoto`) либо текст; подпись собирается из ПОЛНОГО текста BODIES (обрезка ≤850 знаков), эмодзи рубрики, время чтения, ссылка на статью, инлайн-кнопки, хештеги.
- После успешной отправки номер пишется в `state/posted.json` ({n, d}) и пушится.
- Рубрики/дайджест: `publish_category.js`, `publish_battle.js`, `publish_tips.js`, `publish_weekly.js` — свои расписания.

## ⚡ Service Worker и PWA (`sw.js`, версия v3)
- **Регистрация:** выполняется в `theme.js` (загружается на всех страницах), только по https.
- **HTML-страницы:** network-first — контент всегда свежий; офлайн → кэш → главная.
- **Статика (CSS/JS/шрифты/картинки):** stale-while-revalidate — мгновенно из кэша + фоновое обновление; версии файлов через `?v=N` подхватываются автоматически.
- **Офлайн-ядро** прекешируется при установке (главная, стили, основные JS, иконки).
- Админка, статистика и `/state/` SW не обслуживает. Обновление: bump `VERSION` + версии статики.

## 🔍 SEO-каркас (`generate_articles.js`)
- Для каждой статьи: canonical, OG-набор, JSON-LD (Article + BreadcrumbList), meta description, редирект-заглушка `article-N.html` → ЧПУ.
- Хабы брендов `brands/*.html` (24 шт.) и тегов `tags/*.html` (11 шт.) по `seo_taxonomy.js` — с OG-тегами и JSON-LD.
- `sitemap.xml` пересобирается при каждой генерации. Fallback OG-картинка: `/og-image.png`.

## Юридическая чистота и Безопасность

1. **152-ФЗ «О персональных данных»:**
   * Сайт **НЕ собирает персональные данные** (нет форм сбора, нет сторонних трекеров, Метрика/GA удалены). Лайки/просмотры/закладки — только в `localStorage` читателя.
   * Документы: `/privacy.html`, `/terms.html`.
2. **436-ФЗ:** бейдж `0+` в футере всех страниц.
3. **Безопасность:**
   * Пароль админки — SHA-256 хэш в `gate.js`; токен бота владелец вводит вручную (хранится в `localStorage` браузера, в коде отсутствует).
   * CSP: `script-src 'self' 'unsafe-inline'; img-src ... https:; connect-src 'self' https:` и т.д.
   * Секреты CI — только GitHub Secrets (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `TELEGRAM_OWNER_CHAT_ID`).
   * Разбор JS-литералов банков в Node — ТОЛЬКО через vm-песочницу (`vm.runInNewContext`), `eval()` запрещён.

## Инструкции для разработчиков и Агентов ИИ

1. **Перед коммитом:** проверяйте синтаксис `node --check <файл>.js`; полный аудит — `node generate_articles.js` (пересобирает все страницы и sitemap).
2. **Генерация страниц:** любое изменение шаблонов генератора требует пересборки `node generate_articles.js`.
3. **Банки данных:** новые записи добавлять только вставкой перед закрывающим маркером (`\n];`, `\n};`) — так автопилот и ручные правки не конфликтуют. Порядок записей ARTICLE_BANK ↔ BODIES ↔ SOURCES ↔ SLUGS должен совпадать (номер статьи = индекс+1).
4. **Запрещено:** `eval()`, хранение токенов в коде, публикация статей короче фильтра длины, обход дедупликации.
5. **Тест автопилота без записи:** `NEWS_DRY_RUN=1 node .github/workflows/fetch_news.js`.
6. **Service Worker:** при изменении sw.js или кэшируемой статики повышайте `VERSION` в sw.js и `?v=N` подключений.
7. **Пуш на GitHub:** `git pull --rebase origin main && git push origin main` (автопилот коммитит параллельно — rebase обязателен). При конфликте: файлы данных (`script.js`, `article_content.js`, `article_images.js`) объединять вручную, сгенерированные страницы — просто пересобрать генератором.
